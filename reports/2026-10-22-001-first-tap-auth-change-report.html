First-Tap Authentication — Change Report

When a new card is generated, the first tap now asks for a Google sign-in. The card links to that account exactly once, later taps skip the gate, the atelier sees who activated each card, and a wrong link can be cleared.

Decisions recorded in the spec

  • Identity links to the card. After sign-in the uid (and the patient's name, from the Google token) is written to the card record — the atelier can see who activated it. No email is stored.
  • Link exactly once. Later sign-ins verify only; a different account is blocked, never overwritten. Session persistence is best-effort (Safari ITP), and the flow tolerates it.
  • First signer wins for existing cards — the migration section covers every pre-feature card, and a wrong first link has a clinician remedy (Unlink).
  • Apple deferred. Google only; the provider list is the single place a second provider joins later.
  • No bypass anywhere. Tests authenticate like patients; the five stored-card suites migrated to real sessions instead of a gate-off switch.
  • Netlify is inactive. Authorized domains: tap.thecharlestonatelier.com + localhost.
  • Deploy prerequisites (DEPLOY.md §8): register the web app apiKey, enable the Google provider, set authorized domains.
