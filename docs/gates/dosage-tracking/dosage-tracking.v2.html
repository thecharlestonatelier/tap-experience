Per-pen start day and time

Design gate v2 · mission dosage-tracking · issue TAP-EXPERIENCE-1

The goal. The patient sets one start day and one clock time per pen. Today one start day covers the whole protocol, and pens in the same band share one clock time. This design splits both. The patient edits them from each pen’s own card. The first logged dose locks them.

What changes

  1. Start day on the card. Each pen card shows started [date] at the top, between the pen name and the remove control. The date is a button.
  2. Calendar modal. Tapping the date opens a month calendar for that pen. Picking a day sets that pen’s start day and nothing else.
  3. Time per pen. Each pen gets its own clock time. Two pens in the Evening band no longer share one.
  4. Lock after logging. After the first logged dose for a pen, its start day and time freeze. The atelier can still correct the start day.
  5. Remove the global schedule editor. The top-level start-day control and its “Set my schedule” sheet go away. The read-only Schedule tab stays as the month view.

Code example

The two reads that change:

// timeFor(pen) — a pen's own value first, then the band, then the default.
function timeFor(pen) {
  const mine = loadTimes();
  return mine[pen.id] || mine[pen.time] || TIME_AT[pen.time] || '09:00';
}

// applyPenStarts(pen) — new order. The first logged dose now beats a typed day.
if (p.atelierStart) { p.startDate = p.atelierStart; return; }
const first = firstDoseDay(p);
if (first) { p.startDate = first; snapshotTime(p); return; }   // locked
if (mine[p.id]) { p.startDate = mine[p.id]; }

Open decisions for the human

1. The lock reverses a tested rule. The current code says a patient who typed the 12th but logged from the 14th is telling us about two unlogged doses, and she is right. The new lock makes the first logged dose win, which overrides that memory. portal/tests/first-dose-start.mjs asserts the old rule on line 101. The issue asks for the lock to protect dose tracking, so this design follows it and flags the reversal here.

2. The issue says “schedule tab”. This design reads that as the top-level editor sheet, not the read-only calendar tab. Confirm the reading.

3. Amended — the dose log keys by pen id. The human chose Option A: key the dose log by pen id, not template. Two same-template pens now log independently, and no dose drops as a duplicate. SPEC-003 §4 and NFR-2 reopen; the architect amends both and the builder migrates existing template-keyed doses.
